Dispatches a coding agent into a GitHub Actions job for the repository of the workspace you are in, and tears those jobs down again.

A window is a throwaway GitHub Actions job that clones your repository, restores one paired Paseo daemon identity, and then waits to be steered from the app. This plugin is the start surface: it reads the repository from the workspace's git remote, picks a free window slot, dispatches the window workflow, and cancels the runs when you are finished with them. The panel shows the repository it detected, its default branch, all five slots, and the app host entries beside the local daemon.

Setup. Set the offload repository — the `owner/repo` that holds `window-loop.yml` and its secrets — under Settings → Plugins → Offload window. The plugin runs `git` and `gh` on the daemon machine, so both must be installed and `gh` must be authenticated with a token that can dispatch workflows in that repository, read its default branch, and cancel its runs. The window needs that repository's Actions secrets; the plugin reads none of them.

Pairing. Each window row carries two actions. **Turn down** cancels every open run of that slot, so the window cannot come back. **Pair** copies the slot's `relay://` pairing string — the one the setup's `scripts/window-identities.sh` prints into `.secrets/offload-secrets.json` and you paste once into the plugin settings — for Paseo's pair-device dialog; once this client holds that window, the same button becomes **Switch**, and it opens the workspace the window job creates at boot. Both need Paseo 0.13.0 or newer: the daemon password is what the relay checks.

Five window slots. Each slot has its own pre-paired daemon identity and its own GitHub Actions concurrency group, so simultaneous dispatches use different slots and a stale slot choice queues instead of colliding. When all five slots are occupied, the plugin refuses the dispatch and names the busy slots and repositories.
